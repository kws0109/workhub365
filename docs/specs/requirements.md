# WorkHub365 요구사항

## 배경과 문제

Microsoft 365를 쓰는 조직은 계정 온보딩/오프보딩, 라이선스 비용 관리, 휴가·근태 관리를 각각 다른 도구(admin center 수작업, 엑셀, 별도 그룹웨어)로 처리한다. M365 네이티브 관리 센터는 다음이 약하다:

- 라이선스 낭비 가시성(미사용/과다 할당을 한눈에 볼 수 없음)
- 오프보딩 자동화(차단→세션 철회→회수→제거를 수작업으로)
- 휴가/근태 같은 그룹웨어 기능(아예 없음)
- 승인 워크플로우(관리 액션에 결재 개념 없음)

국내 시장에는 M365 전용 관리도구가 사실상 공백이다(CSP 리셀러와 범용 SaaS 자산관리 도구만 존재).

## 제품 비전

"별도 인프라 없이 M365 인증·데이터를 그대로 활용"하는 경량 그룹웨어. 직원은 M365 계정으로 로그인해 휴가·근태를 쓰고, 관리자는 온보딩/오프보딩·라이선스를 자동화하며, AI 어시스턴트가 자연어로 이 액션들을 대행한다(위험 액션은 승인 게이트).

## 사용자 역할

| 역할 | 설명 | 주요 화면 |
|---|---|---|
| employee | 일반 직원 | 휴가 신청, 출퇴근 체크, 내 현황 |
| manager | 결재자 | employee 화면 + 승인함, 팀 캘린더 |
| admin | IT 관리자 | 전체 + 라이선스 대시보드, 온보딩/오프보딩, AI 어시스턴트 |

## 모듈별 요구사항

### M1. SaaS/라이선스 대시보드 (읽기 전용)

- R1.1 테넌트 보유 SKU별 총량/할당/잔여를 표시한다 (`/subscribedSkus`)
- R1.2 사용자별 할당 라이선스와 마지막 로그인 시각을 결합해 "비활성 사용자 × 라이선스" 매트릭스를 보여준다 (30/60/90일 기준 선택)
- R1.3 미사용 라이선스의 월간 낭비 금액을 원화로 환산해 표시한다 (SKU 단가는 설정 가능한 단가표 사용)
- R1.4 다운그레이드/회수 추천 목록을 생성한다 (근거 표시)
- 수용 기준: 실제 테넌트 연결 시 대시보드 로드 5초 이내, 단가표 수정 시 금액 즉시 반영, 낭비 금액 계산 로직 단위 테스트 통과

### M2. 온보딩/오프보딩 마법사 (쓰기)

- R2.1 온보딩: 이름/부서/직급 입력 → 계정 생성 + 임시 비밀번호 발급 + 라이선스 할당 + 그룹 배정을 단계별로 실행하고 진행 상황을 표시한다
- R2.2 오프보딩: 대상 선택 → 로그인 차단 → 세션 철회 → 라이선스 회수 → 그룹 제거를 단계별로 실행한다
- R2.3 각 단계는 실패 시 해당 단계부터 재시도 가능하다
- R2.4 모든 실행은 감사 로그(실행자/대상/액션/시각/결과)를 남긴다
- R2.5 오프보딩 실행 전 확인 다이얼로그(대상 요약 표시)를 거친다
- 제외: 공유 메일박스 전환(Graph 미지원 — README 한계에 명시)
- 수용 기준: 온보딩으로 만든 계정이 M365 admin center에서 확인 가능, 오프보딩 후 대상 계정 로그인 불가

### M3. 휴가 관리 + 승인 워크플로우

- R3.1 직원은 휴가(연차/반차/병가)를 신청한다 (기간, 사유)
- R3.2 결재선(1~2단계)을 따라 승인/반려된다. 반려 시 사유 필수
  - 3일 초과 휴가는 유형 무관 2단계(1차 manager/admin → 최종 admin, **서로 다른 사람**)
  - manager는 자기 부서의 신청만 결재·열람 (admin은 전체)
- R3.3 승인 완료 시 잔여 연차가 차감된다 (연차·반차만, 병가는 기록만. 반차 0.5일)
- R3.4 팀 캘린더에서 부서원 휴가 현황을 월 단위로 본다 (휴일 표시 포함)
- R3.5 (스트레치) 승인 완료 시 신청자 Outlook 캘린더에 이벤트를 생성한다
- R3.6 휴가 일수는 **근무일 기준**: 주말과 휴일(공휴일+전사 휴일)을 제외하고 계산한다
- R3.7 주말·휴일에 걸린 **단일 휴가(반차 포함)는 제출 전에 차단**한다 (폼에서 버튼 비활성 + 사유 표시, 서버 이중 검증)
- R3.8 같은 사용자의 기간이 겹치는 활성 신청(대기/1차/승인)은 생성·승인 단계 모두에서 거부한다
- 수용 기준: 승인 상태 전이(신청→1차승인→최종승인/반려)가 상태머신 단위 테스트 통과, 이중 차감 없음, 동일 결재자의 2단계 단독 통과 불가

### M3-1. 휴일 관리

- R3-1.1 국내 공휴일(대체공휴일 포함)을 외부 API(Nager.Date)에서 연도 단위로 자동 수집해 DB에 캐시한다. API 실패 시 기존 캐시로 동작
- R3-1.2 admin은 전사 휴일/임시 공휴일을 추가·삭제할 수 있고, 연도별 공휴일 재동기화를 실행할 수 있다 (감사 로그 기록)
- R3-1.3 휴일은 캘린더에 표시되고 휴가 일수 계산에서 제외된다

### M4. 근태 관리

- R4.1 직원은 출근/퇴근을 체크인/아웃한다 (하루 1회 쌍, 수정 요청은 관리자 승인)
- R4.2 주간 근무시간이 자동 집계된다 (KST 주 단위, 월~일)
- R4.3 주 근무시간이 임계값(기본 52시간)에 근접/초과하면 본인과 관리자에게 경고를 표시한다
- 수용 기준: 주간 집계 로직(경계: 자정 넘김, 주 경계) 단위 테스트 통과

### M6. 기안(전자결재)

- R6.1 직원은 유형(경비 신청/데이터 반출 신청/휴직 신청/구매 요청)을 선택해 기안을 작성한다 — 유형별로 미리 정의된 입력 필드(템플릿)가 세팅된다
- R6.2 결재선은 유형별 규칙(예: 부서 매니저 → 관리자)으로 **자동 구성**되며, 작성자가 추가·삭제·순서 변경할 수 있다 (본인 제외, 최대 5명, 중복 불가)
- R6.3 결재는 순차 진행: 1차부터 차례로 승인, 전원 승인 시 완결. 반려 시 즉시 종결(사유 필수)
- R6.4 결재가 시작되기 전에는 작성자가 회수할 수 있다
- R6.5 결재함에는 "현재 내 차례"인 기안만 표시된다
- R6.6 열람은 작성자·결재선 구성원·관리자만 가능하다 (기안에는 민감 정보 포함 가능)
- R6.7 상신/승인/반려/회수는 감사 로그를 남긴다
- 수용 기준: 단계 전이 순수 함수 단위 테스트 통과, 동시 결재 시 이중 처리 불가(조건부 전이), 템플릿 외 필드 주입 불가

### M7. 업무 포털 셸 (사이드바·홈)

앱이 "하루 업무의 시작점(포털)" 역할을 하도록 셸을 정비한다. 원칙: M365를 대체하지 않고 연결한다 — 콘텐츠 임베드(iframe)는 하지 않는다(Microsoft가 프레이밍을 차단하며, 경량 애드온 정체성과도 어긋남).

- R7.1 사이드바 메뉴를 "내 업무"(대시보드/휴가/기안/근태)와 "관리"(라이선스/온보딩·오프보딩/AI 어시스턴트/감사 로그) 두 섹션으로 구분하고, 각 메뉴에 아이콘을 표시한다 (역할별 노출은 현행 유지)
- R7.2 기안 메뉴에 "현재 내 차례"인 미결 건수 배지를 표시한다. 값은 서버 렌더 시점 스냅샷이며 결재 액션의 revalidate로 갱신된다 (실시간 폴링은 하지 않는다)
- R7.3 사이드바 하단에 M365 앱 바로가기 섹션을 둔다: Outlook 메일/캘린더, Teams, OneDrive, Planner를 새 탭으로 연다. 외부 이동임을 아이콘으로 표시하고 시각적 위계는 내부 메뉴보다 낮춘다
- R7.4 (후속) 홈 대시보드를 실데이터 위젯 그리드로 교체한다: 프로필·근무 상태 카드, 결재 대기·잔여 연차·주간 근무시간 타일, 내 기안 최근 목록. M365 실시간 카운트(안읽은 메일·오늘 일정)는 매 방문 렌더링되는 홈에서만 조회하고 레이아웃(사이드바)에는 두지 않는다 — 신선도가 보장되지 않는 위치에 실시간 숫자를 두면 신뢰를 깎는다
- 수용 기준: 배지 건수가 결재함 목록 건수와 일치, 외부 링크는 새 탭으로 열림, employee 화면에 관리 섹션 미노출

### M5. AI 어시스턴트

- R5.1 관리자는 채팅 패널에서 자연어로 조회·관리 액션을 요청한다
  - 예: "김철수 계정 만들고 영업팀 권한 줘" / "이번 주 52시간 넘을 것 같은 사람?" / "미사용 라이선스 낭비 얼마야?"
- R5.2 어시스턴트의 도구는 MCP 서버 패키지로 분리 구현한다 (독립 실행 가능)
- R5.3 되돌리기 어려운 액션(계정 차단·삭제, 라이선스 회수, 세션 철회, 그룹 제거, 계정 생성)은 도구가 `approval_required`를 반환하고, UI 승인 카드에서 사용자가 확인해야 실행된다
- R5.4 어시스턴트의 모든 도구 실행도 감사 로그를 남긴다
- 수용 기준: 승인 없이 파괴 액션이 실행되는 경로가 존재하지 않음(시나리오 테스트), 도구 호출 실패 시 사용자에게 원인 표시

## 비기능 요구사항

- N1 인증: 직원 로그인은 Entra ID SSO만 (자체 비밀번호 없음)
- N2 권한: 역할(role) 기반 화면/API 접근 제어. employee가 admin API를 호출하면 403
- N3 시크릿: 환경변수로만 관리, 로그 미출력
- N4 감사: 모든 관리 쓰기 액션 기록
- N5 배포: Vercel, 배포 URL로 데모 가능
- N6 투명성: 개발 과정(스펙, 커밋, 회고)을 공개 리포 + Wiki에 기록
