# 데모 시나리오 대본

목표: 6~7분 안에 "M365 위에 얹히는 경량 그룹웨어 + 관리 자동화 + 승인 게이트 AI"를 실테넌트로 증명한다.
녹화 전 준비와 장면별 [보여줄 것 / 말할 것]을 정리한 대본.

## 녹화 전 준비

- [ ] admin(김 우성) 로그인 세션 확보, 데모 계정 1개는 로그인 가능 상태로
- [ ] `node scripts/seed-leave-demo.mjs` — 팀·휴가 데이터 리셋
- [ ] 결재함에 미결 기안 1건, 오늘 출근 체크 전 상태로 시작
- [ ] 어시스턴트 데모용 대상 계정 지정: 비활성(never/차단) 계정 1개 (예: fin1)
- [ ] 브라우저 줌 110%, 알림 끄기, 1920×1080 녹화

## 장면 1 — 업무 포털 홈 (40초)

- **보여줄 것**: 로그인 → 홈 대시보드. 근무 상태 카드에서 [출근] 클릭 → 카드가 "근무 중"으로. 결재 대기·잔여 연차·주간 근무 게이지·안읽은 메일/오늘 일정 위젯. 사이드바 기안 미결 배지와 M365 앱 런처
- **말할 것**: "M365 계정으로 SSO 로그인하면 업무 시작점이 되는 포털입니다. 위젯은 전부 실데이터 — 오른쪽 두 개는 위임 Graph로 내 메일함과 일정을 읽습니다. 위임 토큰은 암호화 쿠키에만 있고 브라우저에 노출되지 않습니다."

## 장면 2 — 라이선스 낭비 (50초)

- **보여줄 것**: 관리 → 라이선스. 낭비 KPI(₩), SKU 현황, 사용자 상태 매트릭스(never/disabled/inactive), 절감 추천. 단가 인라인 편집 1회
- **말할 것**: "E3 25석 테넌트에서 미할당 12석 + 휴면 보유자를 원화로 환산해 월 낭비를 보여줍니다. 마지막 로그인은 Entra P1의 signInActivity를 쓰고, 권한이 없으면 '알 수 없음'으로 강등됩니다."

## 장면 3 — AI 어시스턴트 + 승인 게이트 (2분, 하이라이트)

- **보여줄 것**:
  1. 관리 → AI 어시스턴트. "미사용 라이선스 낭비 얼마야?" → 도구 칩(get_license_overview)과 스트리밍 답변
  2. "한은우 E3 라이선스 회수해줘" → find_users → get_user_detail 체인 → **승인 카드** 등장 (승인 대기 배지, 입력 JSON, 15분 만료 안내)
  3. [승인하고 실행] → "실행 완료" + 결과 JSON. 이어서 같은 요청을 한 번 더 만들고 이번엔 [거부]
  4. 관리 → 감사 로그: `assistant.tool.*`, `assistant.approval.request` 행들 (실행자에 AI 배지)
- **말할 것**: "위험 액션은 AI가 직접 실행할 수 없습니다. 도구가 approval_required를 반환하고 관리자가 카드에서 승인해야 실행됩니다. 승인은 DB 조건부 UPDATE로 클레임해서 두 탭에서 동시에 눌러도 정확히 1회만 실행됩니다. 모든 도구 실행은 감사 로그에 남습니다. 이 도구들은 MCP 서버 패키지라 Claude Desktop에 붙일 수도 있는데, 그 경로에서도 변경 액션은 실행이 안 됩니다 — 게이트가 구조적으로 강제되기 때문입니다."

## 장면 4 — 오프보딩 파이프라인 (50초)

- **보여줄 것**: 온보딩/오프보딩 → 방금 라이선스를 회수한 비활성 계정으로 오프보딩 실행 — 차단 → 세션 철회 → 라이선스 회수 → 그룹 제거 단계가 스트리밍으로 진행. (가능하면 한 단계 실패 후 "실패 단계부터 재시도" 시연)
- **말할 것**: "퇴사 처리를 파이프라인으로 자동화합니다. 단계별 진행이 실시간으로 스트리밍되고, 중간에 실패하면 실패 지점부터 재시도합니다. 동적 그룹은 자동으로 건너뜁니다."

## 장면 5 — 휴가·근태 (50초)

- **보여줄 것**: 휴가 캘린더에서 날짜 클릭 → 신청 모달 → (다른 계정 또는 사전 준비된 신청 건으로) 결재 승인 → 잔여 연차 차감. 근태 화면의 주간 집계·52시간 게이지
- **말할 것**: "휴가는 결재선을 거쳐 승인되면 연차가 차감됩니다. 공휴일은 자동 수집돼 주말·휴일 신청은 원천 차단됩니다. 근태는 KST 주 단위로 집계해 52시간 초과를 경고합니다."

## 장면 5-1 — 인사 정정 (50초, Phase 8)

> 시드 스크립트(`seed-leave-demo.mjs`)는 잔여 연차를 초기값으로 되돌린다. **시드를 먼저 돌리고 그 다음에 정정을 시연**할 것.

- **보여줄 것**: 근태·휴가 4번째 탭 "인사 정정" → 직원 선택 → ① 퇴근을 깜빡한 "근무 중" 행에서 **출근 시각 입력이 잠겨 있는 것**을 보여주고 퇴근 시각만 채워 닫기 ② 기록 없는 날에 출퇴근 대리 입력 → 주간 합계 반영 ③ 승인된 연차를 5일 → 3일로 정정 → 잔여 연차가 +2 복원되는 것 ④ 감사 로그에서 `attendance.correct` 검색 → before/after 스냅샷
- **말할 것**: "인사 담당자는 타인의 근태·휴가를 정정할 수 있습니다. 권한은 결재 서열과 별개인 플래그라, 인사팀 매니저가 결재권을 잃지 않고 인사 권한만 추가로 가질 수 있습니다. 정정은 사유가 필수이고 전후 스냅샷이 감사 로그에 남으며, 본인 기록은 관리자도 고칠 수 없습니다. 승인된 휴가의 일수를 줄이면 잔여 연차가 자동으로 재정산됩니다 — 반대로 늘리는 건 결재 동의 범위를 벗어나므로 막혀 있습니다."

## 장면 6 — 기안(전자결재) (40초)

- **보여줄 것**: 기안 → 새 기안(경비) → 자동 결재선 확인 → 상신. 결재함에서 승인 → 사이드바 미결 배지 소멸
- **말할 것**: "경비·데이터 반출 같은 템플릿으로 기안을 올리면 부서장→관리자 결재선이 자동 구성됩니다. 문서는 제출 시점 스냅샷으로 보존됩니다."

- **말할 것**: "모든 관리 쓰기 액션은 감사 로그에 남습니다. 이 프로젝트는 AI 에이전트 주도 spec-driven 개발로 만들어졌고, 스펙·프롬프트 로그·리뷰에서 잡힌 결함까지 전 과정이 공개 리포에 기록돼 있습니다."
